# Change Skill, Change Life

## 一句话定位

一个帮助用户发布“我能教的”和“我想学的”，通过双向技能匹配完成低成本学习交换的平台。

## 产品痛点

- 报班成本较高，用户希望通过真实交流获得更灵活的学习方式。
- 自学容易缺少反馈和陪伴，难以持续完成学习目标。
- 许多人拥有可分享的技能，却缺少发现学习者和建立连接的渠道。
- 传统技能平台通常只解决“找老师”，没有解决双方如何互相交换、如何约定具体成果的问题。

## 核心功能

- **发现技能**：浏览用户发布的教学技能和学习目标。
- **搜索与筛选**：按关键词、技能类别、线上/线下方式等条件查找匹配对象。
- **双向匹配**：优先推荐“对方能教我想学的，我能教对方想学的”用户。
- **匹配理由**：展示技能互补、学习方式和时间等匹配依据。
- **技能详情**：查看教学内容、学习目标、个人介绍和可用时间。
- **发起交换**：填写双方交换内容、学习成果、时间和时长。
- **我的交换**：查看发出和收到的申请，并管理交换状态。
- **发布技能**：同时维护“我能教”和“我想学”的技能信息。
- **个人资料**：管理技能、学习目标、可用时间及个人简介。
- **演示降级**：后端接口不可用时，前端自动使用内置演示数据，保证雏形可访问和可体验。

## 核心用户流程

1. 用户进入“发现技能”，浏览或搜索感兴趣的技能。
2. 用户打开技能详情，查看对方能教什么、想学什么以及匹配理由。
3. 用户点击“发起交换”，填写自己的教学内容、学习内容、预计时间和交换时长。
4. 对方在“我的交换”中查看申请，并接受、拒绝或取消交换。
5. 双方按照约定完成一次技能交换。
6. 后续可补充完成确认、评价和交换记录，形成可信的社区履历。

## 匹配逻辑

当前版本采用易解释的规则匹配，重点保证用户能理解“为什么推荐这个人”：

1. **双向技能互补**：用户 A 的“想学”与用户 B 的“能教”匹配，同时用户 B 的“想学”与用户 A 的“能教”匹配时，优先级最高。
2. **单向技能匹配**：一方能教另一方想学的技能时，仍然可以推荐，但标记为单向匹配。
3. **学习方式适配**：线上、线下或同城等方式相同时，提高匹配优先级。
4. **时间可约**：双方存在重叠的空闲时段时，提高匹配优先级。
5. **内容具体度**：带有明确学习成果和教学内容的技能，比泛化的技能名称更容易进入推荐结果。

匹配结果会通过标签和文案解释，例如：“你会 Python，想学手机摄影；对方会手机摄影，想学 Python，因此形成双向互补。”

## 技术结构

```text
浏览器
  |
  | HTTP / JSON
  v
静态前端（HTML + CSS + JavaScript）
  |
  v
Node.js + Express API
  |
  v
当前版本：内存演示数据
后续版本：PostgreSQL / Supabase 等持久化数据库
```

### 前端

- 原生 HTML、CSS、JavaScript，便于快速部署和演示。
- 使用响应式布局，支持桌面端和移动端浏览。
- 通过 Fetch API 请求技能和交换记录接口。
- API 不可用时自动回退到演示数据，保证核心页面仍可体验。

### 后端

- Node.js + Express。
- `GET /api/health`：健康检查。
- `GET /api/skills`：查询技能，支持关键词和 JSON/CSV 格式。
- `GET /api/exchanges`：查询交换申请，可按状态筛选。
- `POST /api/exchanges`：创建交换申请。
- `PATCH /api/exchanges/:id`：更新交换申请状态。
- 当前使用内存数据，适合笔试雏形；正式版本需要接入数据库和用户认证。

## 本地启动

### 方式一：仅启动前端

适合快速查看页面和体验演示数据。

```powershell
cd Change-Skill-Change-Life
py -m http.server 4173
```

打开：`http://localhost:4173`

### 方式二：前端 + 后端

先启动后端：

```powershell
cd Change-Skill-Change-Life/server
npm install
npm start
```

后端默认运行在：`http://localhost:3001`

再打开一个终端启动前端：

```powershell
cd Change-Skill-Change-Life
py -m http.server 4173
```

打开：`http://localhost:4173`

## 部署建议

推荐采用前后端分离部署：

- 前端部署到 Vercel、Netlify 或 GitHub Pages。
- 后端部署到 Render、Railway 或其他支持 Node.js 的平台。
- 通过环境变量配置前端 API 地址。
- 后端绑定平台提供的 `PORT`，并提供健康检查接口。
- 使用固定生产域名，确保面试官在后续 48 小时内可以持续访问同一个链接。
- 正式版本接入数据库、用户认证、CORS 白名单、日志和错误监控。

部署前应使用无痕窗口验证：无需登录即可打开首页、页面刷新正常、核心 API 可访问、手机端布局不溢出。

## 演示说明

建议面试官按照以下路径体验：

1. 在“发现技能”中搜索 `Python` 或 `摄影`。
2. 打开一个技能卡片，查看双方技能和匹配理由。
3. 点击“发起交换”，填写具体的教学内容、学习目标和时间。
4. 进入“我的交换”，查看申请状态和交换详情。
5. 进入“发布技能”，查看如何同时发布“我能教的”和“我想学的”。

当前版本是可交互产品雏形，数据以演示数据和内存数据为主，不代表已经接入真实用户体系。核心展示重点是：从技能发布、匹配解释到交换申请的完整闭环。

## 后续 48 小时迭代

### 第一阶段：可用性完善

- 接入 Supabase 或 PostgreSQL，持久化用户、技能、交换申请和评价数据。
- 增加注册、登录和个人身份信息管理。
- 实现双方申请状态的实时同步。
- 增加时间冲突校验、重复申请校验和取消原因。

### 第二阶段：信任与效率

- 增加交换完成确认、双方评价和举报功能。
- 展示作品链接、教学案例和完成次数，降低首次交换的不确定性。
- 增加站内消息或轻量聊天，帮助双方确认学习目标。
- 优化匹配排序，引入技能标签、水平、地点和时间权重。

### 第三阶段：产品增长

- 增加积分或信用机制，支持无法直接双向交换时的间接交换。
- 增加热门技能、附近用户和新手任务等发现入口。
- 增加数据看板，观察搜索、发起申请、接受申请和完成交换等关键转化指标。
- 根据真实用户反馈继续优化信息结构和移动端体验。
